# Implementation Plan — WinniePro Remodeling Portfolio

## Overview

Build a professional remodeling portfolio website on top of the existing Next.js 14 + AWS Amplify Gen2 template. The current app is a basic Todo demo. This plan replaces it entirely with a portfolio showcasing remodeling projects organized by category and customer, with a mobile-first upload flow and admin dashboard.

**Stack (no new deps required):** Next.js 14, TypeScript, AWS Amplify Gen2, `@aws-amplify/ui-react ^6.5.5`, `aws-amplify ^6.6.6`, CSS Modules.

**Assumptions:**
- S3 bucket is named with Amplify's auto-generated UUID suffix; the `name` attribute in `defineStorage` is `'winniepro-photos'` (friendly name only — Amplify assigns the real bucket name).
- All photos are stored under the path `photos/{projectId}/{uuid}.{ext}` in the single S3 bucket.
- `amplify_outputs.json` does not exist in git (expected — generated by `npx ampx sandbox` at dev time).
- Authorization: guests can read projects and photos; only authenticated users can write.
- No server components for data fetching — all pages are `'use client'` using `generateClient<Schema>()` directly, matching the existing pattern.
- Image display uses Amplify `getUrl()` (returns a pre-signed URL string) rather than a custom CloudFront domain.

**Manual steps the user must take:**
1. Run `npx ampx sandbox` (or `npx ampx sandbox --once`) after the backend files are committed to deploy the Amplify backend (creates DynamoDB tables, S3 bucket, generates `amplify_outputs.json`).
2. Run `npm run dev` only after `amplify_outputs.json` exists.
3. To deploy to production: push to the connected Amplify Hosting branch — `amplify.yml` handles CI/CD automatically.

## Notes for implementer

- **`amplify_outputs.json` is absent** from the repo. The `AmplifyProvider` must guard against its absence at build time (use a `try/catch` around the import or a conditional). The app will not function locally until `npx ampx sandbox` has been run.
- **Authorization mode:** The new schema uses `userPool` as default auth mode for the data client, so `generateClient<Schema>()` in upload/admin pages should pass `{ authMode: 'userPool' }` — or use `generateClient<Schema>({ authMode: 'userPool' })`. Public pages use the default (which falls back to `apiKey` or `iam` for guest reads, depending on what Amplify configures).
- **HEIC support:** HEIC files can be selected via the file input on iOS. The browser will not preview them via `URL.createObjectURL` with a working thumbnail on all platforms — show the filename and a generic image icon as fallback for HEIC previews.
- **Photo deletion from S3:** When deleting a project in admin, the DynamoDB Photo records are deleted but the S3 objects remain (Amplify Storage does not cascade-delete). This is acceptable for v1; add `remove({ path: photo.s3Key })` calls if the user wants full cleanup.
- **`app/page.module.css`** (the original template file) can be deleted as `page.tsx` will use inline styles or `globals.css` classes — or leave it empty; the build does not break either way.
