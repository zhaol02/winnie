### ProjectCard auth mode gap

The Pass 2 fix applied `authMode: 'apiKey'` to `app/page.tsx` and `app/projects/[id]/page.tsx`, but `ProjectCard.tsx` has its own module-scope `generateClient` call:

```ts
// app/components/ProjectCard.tsx:12
const client = generateClient<Schema>();
```

`ProjectCard` is rendered by the homepage grid for every project. It calls `client.models.Photo.list({ filter: { projectId: { eq: project.id } } })` to find the cover photo, then `getUrl` to resolve the S3 URL. Both operations require read access on `Photo`, which the schema permits via `allow.guest().to(['read'])` — but only when the auth mode is `apiKey`. With the default `userPool` mode and no authenticated session, AppSync rejects the request and the card displays a placeholder forever.

The fix is one line:

```ts
const client = generateClient<Schema>({ authMode: 'apiKey' });
```

This is the same pattern already used in `app/page.tsx` and `app/projects/[id]/page.tsx`.

</details>
