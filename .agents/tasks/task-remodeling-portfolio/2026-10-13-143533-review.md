## High-level view

All four pages exist and meet the feature spec. Auth gating is correct. TypeScript types are clean — `Schema["Project"]["type"]` and `Schema["Photo"]["type"]` are used throughout with no `any`. CSS Modules only; no new UI libraries. The three palette colors are defined as CSS variables and applied consistently across all modules.

The AmplifyProvider config-race concern from the prior pass is addressed: rendering is now blocked until config resolves, so `useEffect` data calls in child components cannot fire before Amplify is ready. Module-scope `generateClient` calls pre-date config but aren't executed until component mount, which is after the block lifts.

The public pages (homepage and project detail) use `generateClient<Schema>()` without an `authMode` override. With `defaultAuthorizationMode: "userPool"`, unauthenticated visitors will hit the userPool auth mode. The schema grants `allow.guest().to(["read"])`, but whether Amplify Gen2 automatically selects API key auth for unauthenticated callers when the default mode is `userPool` needs verification against a live sandbox.

The admin N+1 remains: each project row triggers a separate `Photo.list` query to count photos. The `photoCount` field was not added to the `Project` model, and no batching was introduced.

### Public page auth mode gap

The data schema sets `defaultAuthorizationMode: "userPool"`. Both public pages create their client as:

```ts
const client = generateClient<Schema>();
```

No `authMode` override. The `allow.guest().to(["read"])` rules on `Project` and `Photo` are backed by the API key auth mode — Amplify Gen2 uses the API key to service unauthenticated read requests. When `generateClient` uses `userPool` as its default and no API key is passed, an unauthenticated visitor's requests go to AppSync with no valid Cognito token, resulting in an auth error.

The fix is:
```ts
const client = generateClient<Schema>({ authMode: 'apiKey' });
```
on `app/page.tsx` and `app/projects/[id]/page.tsx`. Upload and admin clients should remain with `userPool` (their write operations require auth). **Likely** — Amplify Gen2 may have a runtime fallback to the next-available auth rule, but relying on undocumented fallback behavior is fragile. Verify in sandbox before shipping.

### N+1 photo count in admin

`AdminDashboard.loadProjects` fetches every project then, for each:

```ts
const { data: photos } = await client.models.Photo.list({
  filter: { projectId: { eq: project.id } },
});
return { project, photoCount: photos?.length ?? 0 };
```

All wrapped in `Promise.all`, so the queries fire in parallel — but they still count as O(n) AppSync operations, each with network round-trip overhead and per-operation DynamoDB cost. This was flagged in the prior review; the fix was not applied. Adding `photoCount: a.integer()` to the `Project` model and incrementing it in `upload/page.tsx` after each successful `Photo.create` would collapse this to zero extra queries. **Confirmed.**
